核心问题#

某些问题都有明确的数学定义，也都可以被描述为有限的计算过程，但它们的计算难度可能截然不同。例如，某些问题虽然理论上可以求解，但随着输入规模增长，所需计算资源可能迅速超过现实条件。

因此，我们引入两个概念：

  • 可计算性（Computability）：一个问题能否被某种算法解决？
  • 计算复杂性（Computational Complexity）：解决问题需要多少计算资源？

算法的数学抽象#

在数学中，我们通常将一个计算问题表示为：

\[ f:X\rightarrow Y. \]

给定输入 \(x\in X\)，要求计算输出：

\[ y=f(x). \]

但并不是所有数学对象都能直接作为计算机输入。我们通常需要将输入编码为有限字符串：

\[ x\in\Sigma^*, \]

其中 \(\Sigma\) 是有限字母表，\(\Sigma^*\) 表示所有有限字符串构成的集合。于是，计算问题可以被统一描述为对有限字符串的处理。

判定问题#

计算复杂性理论经常研究判定问题（Decision Problem）。一个判定问题的答案只有两种：

\[ {\text{YES},\text{NO}}. \]

数学上，可以将其表示为一个语言：

\[ L\subseteq\Sigma^*. \]

对于输入 \(x\)，问题就是判断：

\[ x\in L? \]

图灵机的基本结构#

1936 年，Alan Turing 提出了图灵机（Turing Machine）模型。它是现代计算理论的基础之一。一台确定性图灵机可以描述为：

\[ M=(Q,\Sigma,\Gamma,\delta,q_0,q_{\mathrm{accept}},q_{\mathrm{reject}}), \]

其中：

  • \(Q\)：有限状态集合；
  • \(\Sigma\)：输入字母表；
  • \(\Gamma\)：纸带字母表；
  • \(\delta\)：状态转移函数；
  • \(q_0\)：初始状态；
  • \(q_{\mathrm{accept}}\)：接受状态；
  • \(q_{\mathrm{reject}}\)：拒绝状态。

图灵机包含：

  1. 一条理论上无限长的纸带；
  2. 一个能够读写纸带符号的读写头；
  3. 一个有限状态控制器。

纸带用于保存计算数据，读写头用于访问和修改数据，状态控制器决定下一步动作。

图灵机的每一步操作由当前状态和当前读取的符号决定。

状态转移#

设当前状态为 \(q\)，读写头读取的符号为 \(a\)。

转移函数给出：

\[ \delta(q,a)=(q’,b,D), \]

其中：

  • \(q’\)：下一状态；
  • \(b\)：写入纸带的符号；
  • \(D\)：读写头移动方向，通常为 L 或 R。

因此，一次计算就是一系列状态转移：

\[ C_0\rightarrow C_1\rightarrow C_2 \rightarrow\cdots. \]

这里 \(C_i\) 表示图灵机在第 \(i\) 步的完整配置，包括状态、纸带内容和读写头位置。

如果最终进入接受状态，则输入被接受；如果进入拒绝状态，则输入被拒绝。

图灵机与现代计算机#

图灵机并不是一种实际计算机的设计方案。它的价值在于提供一个足够简单、足够严格的计算模型。

现代计算机拥有CPU、内存、磁盘、输入输出设备、多级存储结构。但对于可计算性理论而言，我们关心的是：这些计算设备是否能够实现某个数学意义上的算法。在适当的抽象条件下，图灵机能够模拟通常意义上的算法计算。这与 Church–Turing 论题有关：

任何直观意义上可有效计算的函数，都可以由图灵机计算。

可计算性：哪些问题根本无法被算法解决？#

图灵机模型不仅能够描述算法，还能证明某些问题不存在通用算法。

停机问题#

考虑一个程序 \(P\) 和输入 \(x\)。

我们希望判断：

\[ P(x)\text{ 是否会最终停止？} \]

这就是停机问题（Halting Problem）。

假设存在一个算法 \(H(P,x)\)，能够正确判断任意程序 \(P\) 在输入 \(x\) 时是否停止：

\[ H(P,x)= \begin{cases} 1,&P(x)\text{ 停止},\\ 0,&P(x)\text{ 不停止}. \end{cases} \]

我们将证明这样的算法不存在。

对角化证明#

假设 \(H\) 存在。

构造一个新程序 \(D(P)\)：

  1. 运行 \(H(P,P)\)；
  2. 如果 \(H(P,P)=1\)，则 \(D(P)\) 无限运行；
  3. 如果 \(H(P,P)=0\)，则 \(D(P)\) 立即停止。

现在考虑：

\[ D(D). \]

只有两种可能。

情况一：\(H(D,D)=1\)。

这意味着 \(D(D)\) 应当停止。但根据 \(D\) 的定义，如果 \(H(D,D)=1\)，它就会无限运行。矛盾。

情况二：\(H(D,D)=0\)。

这意味着 \(D(D)\) 不会停止。但根据 \(D\) 的定义，如果 \(H(D,D)=0\)，它就会立即停止。仍然矛盾。因此，最初的假设不成立：

\[ \boxed{ \text{不存在能够判断任意程序是否停止的通用算法。} } \]

计算资源：时间复杂度与空间复杂度#

输入规模#

考虑一个算法 \(A\)。我们希望衡量其运行时间与输入规模之间的关系。设输入为 \(x\)，其长度为：

\[ n=|x|. \]

对于二进制编码的整数，输入长度通常与整数的数值大小不同。因此，复杂度分析必须以编码长度为基础，而不是直接使用整数数值。

时间复杂度#

设算法在输入 \(x\) 上执行的步骤数为：

\[ T_A(x). \]

最坏情况时间复杂度定义为：

\[ T_A(n)= \max_{|x|=n}T_A(x). \]

我们通常使用渐近符号描述增长速度。

大 O 记号#

若存在常数 \(c>0\) 和 \(n_0\)，使得对所有 \(n\geq n_0\)：

\[ f(n)\leq cg(n), \]

则称：

\[ f(n)=O(g(n)). \]

大 \(\Omega\) 记号#

若存在常数 \(c>0\) 和 \(n_0\)，使得：

\[ f(n)\geq cg(n), \]

则称：

\[ f(n)=\Omega(g(n)). \]

大 \(\Theta\) 记号#

若同时有：

\[ f(n)=O(g(n)) \]

和：

\[ f(n)=\Omega(g(n)), \]

则：

\[ f(n)=\Theta(g(n)). \]

空间复杂度#

空间复杂度衡量计算过程中使用的存储资源。

设：

\[ S_A(x) \]

表示算法使用的工作空间。

则最坏情况空间复杂度为：

\[ S_A(n)= \max_{|x|=n}S_A(x). \]

在复杂性理论中，通常会明确是否计入输入存储空间。

P 类问题：能够高效求解的问题#

P 的定义#

P 类（Polynomial Time）是所有能够由确定性图灵机在多项式时间内判定的语言集合。

形式化地：

\[ \boxed{ P= \bigcup_{k\geq1}TIME(n^k) } \]

其中 \(TIME(n^k)\) 表示能够在 \(O(n^k)\) 时间内完成判定的语言集合。

直观上，P 包含了能够在多项式时间内求解的判定问题。需要注意，P 是关于渐近复杂度的数学类别。比如一个 \(O(n^{100})\) 的算法仍然属于多项式时间，但现实中可能完全不可行。

因此：

\[ \boxed{ \text{多项式时间}\neq\text{实际运行足够快} } \]

NP 类问题：容易验证，不一定容易求解#

从数独问题出发#

考虑一个数独问题。给定一个未完成的数独，我们希望判断是否存在合法填法。寻找一个解可能需要大量尝试。但如果有人已经给出一个完整填法，我们可以快速检查：

  • 每一行是否满足规则；
  • 每一列是否满足规则；
  • 每个宫格是否满足规则。

也就是说：

找到解可能困难，但验证一个候选解可能容易。

这就是 NP 类问题的基本思想。

NP 的形式化定义#

NP 表示 Non-deterministic Polynomial Time。它可以通过非确定性图灵机在多项式时间内判定来定义。

另一种等价定义是：

一个语言 \(L\) 属于 NP，当且仅当存在一个多项式时间验证器 \(V(x,w)\)，使得：

\[ \boxed{ x\in L \iff \exists w,\quad V(x,w)=1 } \]

其中：

  • \(x\)：原始输入；
  • \(w\)：证书（Certificate）；
  • \(V\)：多项式时间验证器。

证书的长度也要求关于输入长度多项式有界。

NP 不等于非多项式时间#

这是一个非常常见的误解。NP 不是“Non-Polynomial”的缩写。它表示非确定性多项式时间。

实际上：

\[ \boxed{P\subseteq NP} \]

因为如果一个问题能够在多项式时间内直接求解，那么当然也能够在多项式时间内验证其答案。

但是否有：

\[ P=NP\quad ? \]

所有能够在多项式时间内验证解的问题，是否也都能够在多项式时间内求解？

目前仍然未知。这是理论计算机科学中最著名的开放问题之一。

多项式时间归约：如何比较问题的难度？#

假设我们已经知道问题 A 很难。能否利用问题 A 的求解算法来解决问题 B？这就是归约（Reduction）的基本思想。

多项式时间归约#

设两个判定问题分别对应语言：

\[ A,B\subseteq\Sigma^*. \]

如果存在一个多项式时间可计算函数：

\[f:\Sigma^* \rightarrow \Sigma^* \]

满足：

\[ \boxed{ x\in A\iff f(x)\in B, } \]

则称：

\[ A\leq_p B. \]

这表示 A 可以在多项式时间内归约到 B。

如果我们能够高效求解 B，就能够高效求解 A。

因此：

\[ A\leq_p B \]

意味着 B 至少不比 A 更容易（相对于这种归约）。

NP-hard 与 NP-complete#

一个问题 \(B\) 称为 NP-hard，如果：

\[ \forall A\in NP,\quad A\leq_p B. \]

即所有 NP 问题都可以多项式时间归约到 B。

如果同时满足：

\[ B\in NP \]

和：

\[ B\text{ 是 NP-hard}, \]

则称 B 为 NP-complete。

SAT 问题#

SAT（Boolean Satisfiability Problem）是经典的 NP-complete 问题。

给定一个布尔公式：

\[ \varphi(x_1,\ldots,x_n), \]

判断是否存在变量赋值使：

\[ \varphi(x_1,\ldots,x_n)=1. \]

Cook–Levin 定理：**SAT 是 NP-complete 的。**这意味着所有 NP 问题都能够多项式时间归约到 SAT。如果有人找到 SAT 的多项式时间算法，那么： \[ P=NP. \]

这就是 SAT 在计算复杂性理论中的特殊地位。

复杂性理论的更大图景#

P 与 NP 只是复杂性理论的一部分。 我们还需要认识一些重要的复杂性类别。

PSPACE#

PSPACE 是能够使用多项式空间完成判定的问题集合。

\[ PSPACE= \bigcup_{k\geq1}SPACE(n^k). \]

EXP#

EXP 是能够在指数时间内求解的问题集合：

\[ EXP= \bigcup_{k\geq1}TIME(2^{n^k}). \]

显然：

\[ P\subseteq EXP. \]

而且可以证明：

\[ P\subsetneq EXP. \]
